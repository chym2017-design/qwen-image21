# 本地模型换装对照实验：整图直接生成(A) vs 抠图生成+贴回原背景(B)

日期：2026-10-14 00:24–02:40 ｜ 目录：`tryon_demo/direct_vs_crop_test_20261014/`
模型：本机 ComfyUI（127.0.0.1:8188）Qwen-Image-2.1（int8）+ viggle turbo LoRA（6 步，采样器 euler）
提示词：`将<image2>的衣服穿到<image1>的人物身上，保持人物面部、姿态和背景不变`

## 0. 结论速览（按用户指定的安全尺寸 683×1024）

| 路线 | 端到端耗时 | 背景保真（漂移） | 备注 |
|---|---|---|---|
| **A 直接生成**（画布 672×1024） | **116.0s** | 3.62（背景被重绘） | 换装不完全：绿裙穿在了毛衣外（毛衣未脱） |
| **B 抠图生成+贴回**（生成画布 288×928） | **87.6s** | **0.25（像素级原背景）** | 快 24%；换装有 2/4 成功率，需重试 |

- 生成耗时 ∝「参考图+画布」总像素：B 用大约 1/3 的总像素量把人物渲染到同等像素高度，
  所以同画质下更快；B 代价是多出抠图环节（约 19s）+ 需后处理/重试。
- 1.57MP 级（长边 1536）输入在本机必触发 swap（见 §4），**输入长边缩到 ~1024 是本机安全姿势**。

## 2. 两条路线

**A 整图直接生成**：原图直接进模型，输出尺寸跟随输入（`resolution` 语义 = 像素预算，
0 = 保持原尺寸），人物与背景都由模型重绘。

**B 抠图生成+贴回**（即 `proc.py::_gen_swap_crop`）：
rembg 抠人像 → 前景 bbox 裁切贴白底 → rembg 抠衣服图 → 裁切贴白底 → 小画布生成 →
生成结果再 rembg 抠人物 → 缩放回 bbox → 贴回原人像（bbox 外背景像素原样保留）。

## 3. 速度实测

### 3.1 小尺寸（683×1024，本次主实验，干净环境）

| 配置 | 画布 | 墙钟 | ComfyUI 自报 | 每步 |
|---|---|---|---|---|
| A 直接生成（resolution=0） | 672×1024 | **116.0s** | 115.3s | 8.8→12s/it |
| B-抠图（人像 11.6s + 衣服 7.8s） | — | 19.4s | — | — |
| B-生成（resolution=0，画布=裁切尺寸） | 288×928 | 58.6s（首跑）/ 32.3s（后续同画布） | 57.9s | 4.5→5.2s/it |
| B-结果抠图 + 贴回 | — | 9.6s + 0.01s | — | — |
| **B 合计** | | **87.6s** | | |

> B 小画布成功换装率实测 **2/4**（两次原样不变）。失败即重试，单次重试 32.3s；
> 若按期望 2 次尝试计，B 实际期望耗时 ≈ 94s~120s。失败判定可由「结果与输入裁切相似度过高」实现。

### 3.2 大尺寸（1024×1536 输入，早期实验 + 内存受限数据）

| 配置 | 画布 | 墙钟 | 备注 |
|---|---|---|---|
| A1 原生（resolution=0） | 1024×1536 (1.57MP) | 522.7s | 两次测量均受内存交换拖累（§4），首步即卡 |
| A2 1024（8190 默认档） | 832×1248 (1.04MP) | **192.7s（干净）** / 702.9s（紧跟大任务后跑，swap 污染） | 同配置方差 3.6 倍，全看内存状态 |
| A4 759（≈B 画布同预算） | 608×928 (0.56MP) | 91.8s | 与 B 的生成 110.8s 同量级，但人物只占画面一小块 |
| A3 512 | 416×640 (0.27MP) | 67.3s | |
| B 抠图生成+贴回 | 生成画布 416×1376 | **143.7s**（生成 110.8s + 抠图 23.3s + 结果抠图 8.7s + 贴 0.01s） | |

### 3.3 速度规律

生成耗时 ≈ 正比于 token 量 ≈「各参考图 + 输出画布」的总像素。同一个人物细节下：
- A 必须把整张照片（人物+背景）都放进画布 → 总像素大；
- B 只渲染人物剪影 bbox → 总像素约 1/3，且人物在画布中占比接近 100%。
这就是 B 更快且人物分辨率更高的原因。

## 4. 重要发现：32GB 机器的内存天花板

- 大画布运行时 ComfyUI 进程 RSS 达 **33GB（物理只有 32GB）**，swap 最高 **17.7GB**。
  组成：text encoder（8B，加载为 fp16 ≈16GB）+ unet int8（6.9GB）+ VAE + 大画布激活。
- 症状：**首步采样 62s（正常）→ 221~251s（swap 中）**；同一配置总时长 192.7s ↔ 702.9s 波动；
  1.57MP 配置连续两次复测都在首步卡死（用户指示后中止）。
- 安全边界实测：总像素（refs+canvas）≈ 3MP 以内（如 1024 档 832×1248×3）可稳定跑干净；
  B 的小画布（≈0.74MP 总量）完全无压力，稳定 4.5~5.2s/it。
- 可用手段：`POST /free {"unload_models":true,"free_memory":true}` 立即释放（RSS 33GB→0.4GB，
  下次任务自动重载，重载约 45s，建议作为定时/卡顿自愈手段）；或把输入长边缩到 ≤1024。

## 5. 画质对比

| 指标 | 小图 A′ | 小图 B′ | 大图 A1 | 大图 A2 | 大图 B3 |
|---|---|---|---|---|---|
| 背景漂移（剪影外平均绝对差，越小越好） | 3.62 | **0.25** | 6.66 | 7.48 | **0.40** |
| 身份相似度（insightface，对比原人像） | 0.698 | 0.709 | 0.8311 | 0.7461 | **0.9098** |

- **背景**：B 路线贴回后背景 == 原图（数值差异仅来自边缘羽化）；A 路线背景必然重绘，
  玻璃橱窗、路砖等结构会变（这正是"保持背景不变"提示词难以 100% 约束的地方）。
- **换装完整度**：
  - A 小图版：绿裙穿在**毛衣外面**（毛衣没脱）——模型把"穿衣服"理解成叠加；
  - B 小图版：绿裙正确替换上衣（但 2/4 概率不换，见 §3.1）；
  - 大图版 A1/A2 与 B3 都把整套下半身也换成了衣服图的牛仔裤+白鞋（模型行为，两路线一致）。
- **B 的贴回伪影与修复**（`patch_leftover.py`，最近真实背景像素精确填充）：
  1. **旧剪影残留**（旧毛衣/白裤比新剪影宽出的条带）：直接贴会露出橙色披肩状残留。
     一键修复：把"旧剪影中未被新剪影覆盖"的区域用最近的真实背景填充后再贴回。
     效果：大图橙色像素 8375→1727，小图 4028→901，视觉上大块残留消失，仅余细描边。
  2. **生成内容伪影**（右侧肩臂橙带）：像素级验证生成图本身在该处 alpha=1.0、内容即橙色针织
     ——是模型在小画布把原毛衣混进生成结果的**生成阶段伪影，贴回环节无法修复**；
     需从提示词/画布/重试侧治理。
- B 后处理总成本：填充 + 重贴 ≈ 0.01~0.05s（可忽略）。

## 7. 落地建议（8190/8191）

1. **输入统一缩到长边 ≤1024** 再进模型（输出尺寸随输入），本机就绕开 swap 悬崖。
2. 试装优先走 **B 抠图路线**：更快（小图 88s vs 116s；大图 144s vs 193s+）、背景真保真、
   身份相似度更高；把「抠图→生成→贴回→残留修复」做成固定流水线（`proc.py` 已有骨架）。
3. B 路线加**换装失败检测与重试**（小画布约 50% 首跑不换装，单次重试 32s 级）。
4. 定时调用 `/free` 或任务间自动 /free，防止连续大任务把机器拖进 swap。
5. 若必须原尺寸直出：建议仅用 512/759 档（67~92s），accept 背景重绘。
